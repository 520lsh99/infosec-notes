### 1. PHP 8.1+ 跑 DVWA 报 500 Internal Server Error

- **日期**：2026-10-21
- **现象**：DVWA 的 SQL 注入页输入 `1'`，浏览器显示 500，而不是预期的 SQL 报错文字。
- **原因**：PHP 8.1 起 `mysqli` 默认把数据库错误抛成异常；DVWA 老代码用 `mysqli_query(...) or die(...)`，接不住异常 → 页面 500。
- **解法**：不改源码，加一个全局 prepend 关掉异常模式。

```bash
cd /tmp/DVWA-master
echo "<?php mysqli_report(MYSQLI_REPORT_OFF);" > prepend.php
sudo php -d auto_prepend_file=/tmp/DVWA-master/prepend.php -S 0.0.0.0:8080
```

- **下次判断**：老 PHP 项目在 PHP 8.1+ 下无故 500，先怀疑 mysqli 异常模式，别急着改代码。

### 2. 终端粘贴出现 `zsh: bad pattern: [200~sudo`

- **日期**：2026-10-21
- **现象**：粘贴 `sudo php -S 0.0.0.0:8080`，终端报 `bad pattern: [200~sudo`。
- **原因**：终端把 bracketed paste 的转义序列 `[200~` 当成了命令的一部分。
- **解法**：改用 `Shift + Ctrl + V` 粘贴，或直接手打。
- **下次判断**：命令开头多出 `[200~`、`^[[` 这类怪字符，就是粘贴方式的问题，重敲即可。

### 3. Docker 拉 `vulnerables/web-dvwa` 一直超时

- **日期**：2026-10-21
- **现象**：`docker pull` 卡在 `Pulling fs layer`，换 1ms.run、腾讯云加速器都一样。
- **原因**：国内直连 Docker Hub 和多家加速器都不稳定，不是配置写错。
- **解法**：放弃 Docker，用系统包直接跑 DVWA（PHP + MariaDB + 内置服务器）。
- **下次判断**：Docker 拉不动别死磕加速器；Docker 只是交付方式，靶场本身能直接跑。

### 4. VirtualBox 虚拟机磁盘显示「无法访问」

- **日期**：2026-10-21
- **现象**：虚拟机明细里 SATA 磁盘写着 `(普通, 无法访问)`，启动报错。
- **原因**：`.vbox` 或 VirtualBox 注册表里还记着**已移动/已删除的旧路径**。常见于「先导入、后挪文件夹」。
- **解法**：

```powershell
VBoxManage unregistervm "虚拟机名"
VBoxManage registervm "D:\VMs\kali\...\xxx.vbox"
VBoxManage modifyvm "虚拟机名" --memory 4096 --cpus 4 --accelerate3d off
```

- **下次判断**：按顺序查三件事——文件还在不在、注册的 Config file 指向哪、是不是导入后搬过家。
- **口诀**：**先放好文件夹，再导入；导入后别再挪。**

### 5. Kali 镜像的 7z 解压与文件放置

- **日期**：2026-10-21
- **现象**：用 Windows 自带解压开 7z，怀疑文件不完整。
- **判断**：解压出的 `.vdi` 应该 **15GB 左右**（Kali 2026.2 实测 15.06GB）；几百 MB 或 0 就是失败。
- **解法**：用 7-Zip 解压到 `D:\VMs\kali\`，先放好再导入。
- **下次判断**：4GB 级别的 7z 别用资源管理器双击解压，容易假死丢文件。

### 7. `/tmp` 里的东西会被系统清理

- **日期**：2026-10-21
- **现象**：DVWA 放 `/tmp/DVWA-master`，过几天可能就没了。
- **原因**：系统会定期清理 `/tmp`。
- **解法**：挪到 `/opt` 或家目录。

```bash
sudo mv /tmp/DVWA-master /opt/dvwa
```

- **下次判断**：需要长期保留的目录，别放 `/tmp`、`/var/tmp`。

### 8. C 盘空间莫名其妙变少

- **日期**：2026-10-21
- **现象**：装完虚拟机后 C 盘只剩几十 GB。
- **原因**：① 虚拟机/下载包默认落 C 盘；② 删除的文件还在回收站，空间没释放。
- **解法**：虚拟机统一放 `D:\VMs`；定期清空回收站；清 `%LOCALAPPDATA%\Temp`。
- **下次判断**：空间少了先看回收站和临时目录，再找大文件。

### 9. 虚拟机关机方式

- **日期**：2026-10-21
- **现象**：习惯点窗口 ✕ 关虚拟机。
- **原因**：✕ 会弹「发送关机信号 / 关闭电源」，选后者等于拔电源，可能坏文件系统。
- **解法**：Kali 里点电源 → Shut Down；或终端 `sudo poweroff`；或菜单「控制 → 发送关机信号」。
- **下次判断**：「关机」= 发信号让系统有序退出；「关闭电源」= 断电，只在卡死时用。

### 10. 快照不是每次都要拍

- **日期**：2026-10-21
- **现象**：以为每次开机都要拍快照。
- **事实**：快照拍一次就一直留在列表里。只在「完成大阶段」或「做危险操作前」再拍。
- **下次判断**：快照占磁盘，最多留 2–3 张：初始干净 / 装好 DVWA / 某实验前。

### 11. Burp 起不来：8080 被靶场占了

- **日期**：2026-10-21
- **现象**：Burp 点启动监听时报 `Failed to start proxy service on 127.0.0.1:8080. Check whether another service is already using this port.`
- **原因**：DVWA 的 PHP 服务器正跑在 `0.0.0.0:8080`，Burp 默认也用 8080。
- **解法**：Burp 监听改 8081（Proxy settings → Edit → Port 8081 → 勾 Running），浏览器代理端口同步改 8081。
- **下次判断**：**靶场用 8080，Burp 用 8081**，固定错开，别让两个工具抢同一个门。

### 12. Fox 抓不到本地请求：Firefox 永不代理 127.0.0.1

- **日期**：2026-10-21
- **现象**：代理设好了，Burp 开着，浏览器能打开 `http://127.0.0.1:8080`，但 HTTP history 里一条都没有。
- **原因**：Firefox 连接设置里写明 `Connections to localhost, 127.0.0.1, and ::1 are never proxied.`——**本地回环地址硬性绕过代理**。
- **解法**：给靶场起个假域名。

```bash
echo "127.0.0.1 dvwa.test" | sudo tee -a /etc/hosts
# 重启 Firefox，访问 http://dvwa.test:8080
```

- **下次判断**：Burp 抓不到本地流量时，先看目标是不是 localhost/127.0.0.1；是就换域名。

### 13. 浏览器报 `The proxy server is refusing connections`

- **日期**：2026-10-21
- **现象**：浏览器提示代理拒绝连接，页面打不开。
- **原因**：代理软件（Burp）没在监听——可能是没启动、端口不对，或监听列表里的 **Running 没勾**。
- **解法**：Burp → Proxy settings → 确认 `127.0.0.1:8081` 的 Running 已勾选；浏览器代理端口一致。
- **判断口诀**：

| 现象 | 含义 |
|---|---|
| proxy refusing connections | 代理没监听（Burp 没开/端口错/没勾 Running） |
| 能开页面但抓不到 | 目标被绕过（No proxy for / localhost） |
| Server not found | DNS 或 hosts 问题 |

### 14. GTK 文件对话框：打字变成搜索，选不到文件

- **日期**：2026-10-21
- **现象**：在 Firefox 上传文件时点 Browse，直接打字，对话框显示 `No Results Found`，找不到文件。
- **原因**：GTK 文件选择器**一打字就进入搜索模式**，不会填到地址栏。
- **解法**：先按 `Esc` 退出搜索，再按 **`Ctrl + L`** 调出地址栏，输入完整路径（如 `/tmp/shell.php`）回车。
- **下次判断**：Linux 文件对话框输了路径却搜不到，就是没进地址栏。

### 15. printf 写 webshell 时变量被吃掉

- **日期**：2026-10-21
- **现象**：`printf '<?php system($_GET["cmd"]); ?>' > shell.php` 生成的文件内容不对或为空。
- **原因**：外层用了双引号，`$_GET` 被 shell 当成变量展开成空。
- **解法**：外层用单引号，内容原样写入：

```bash
printf '%s' '<?php system($_GET["cmd"]); ?>' > /tmp/shell.php
```

- **下次判断**：写含 `$` 的内容到文件，外层一律用单引号或 heredoc（带引号版）。

### 16. 虚拟机卡在「正在关闭」，菜单「停止」是灰的

- **日期**：2026-11-08
- **现象**：虚拟机关机后一直显示「正在关闭」，点关闭窗口无效，「停止」菜单灰掉点不了。
- **原因**：ACPI 关机信号发出后，Guest 里某个进程没退出，VirtualBox 一直等；窗口关了但进程还在跑（任务管理器里 `VirtualBoxVM.exe` 占着约 3.4GB）。
- **解法**：任务管理器（`Ctrl+Shift+Esc`）→ 找到 **VirtualBox Virtual Machine (...)** / `VirtualBoxVM.exe` → **结束任务**。
- 结果状态变成 **「异常退出 / Aborted」**，这是正常的，虚拟磁盘文件不受影响，下次直接启动即可。
- **下次判断**：
  - 先等 30–60 秒
  - 不行 → 菜单「控制 → 停止 → 关闭电源」
  - 还不行 → 任务管理器结束进程
  - 开机若提示文件系统检查（fsck），让它跑完

**避免再发生**：关机优先在 Kali 终端 `sudo poweroff`，别点窗口 ✕。

### 17. TCP 靶机：不是网址，要连端口手发 HTTP

- **日期**：2026-11-10
- **现象**：平台给的是 `openssl s_client -connect xxx:9999` 这种命令，浏览器打不开，不知道该访问哪。
- **原因**：这是 **TCP 靶机**，只暴露一个端口，需要自己连上去、手打 HTTP 请求报文。
- **解法**：

```bash
openssl s_client -connect xxxx.tcp-ctf2.dasctf.com:9999 -servername 同域名
# 连上后手打：
GET /Secret.php HTTP/1.1
Host: xxxx.tcp-ctf2.dasctf.com:9999
Connection: close

```

- **要点**：
  - 请求最后**必须有空行**（再按一次回车），否则服务器不响应
  - 带 `Connection: close` 时回完就断，要发下一个请求得**重连**（`↑` 调出命令）
  - `verify error: self-signed certificate`、`SSL_shutdown ... while in init` 都是正常现象
  - 路径大小写敏感（`/Secret.php`）
- **下次判断**：平台给的访问信息是 `openssl`/`nc`/`remote(...)` 而不是 URL → 就是 TCP 靶机。

### 18. 对话式终端一次粘多行 → 缓冲区错乱

- **日期**：2026-11-11
- **现象**：在交互式终端（金库审计题）里一次粘贴 10 行 `WITHDRAW 1`，只有 1~2 条被执行，还出现 `数量必须是整数`、`格式: 命令 数量` 这类报错；再输入 `STATUS` 也被拼到残行上。
- **原因**：服务端按行读取输入，批量粘贴时多行堆在缓冲区，被当成同一条命令或残留在下一行前。
- **解法**：
  - **一次只发一条**，看到提示符（如 `[探索] >`）再发下一条
  - 批量脚本要用带延时的管道：`{ echo CMD1; sleep 0.3; echo CMD2; sleep 0.3; } | openssl s_client ... -quiet`
- **下次判断**：交互式终端里命令被吞/拼接/报「格式不对」，先怀疑批量粘贴。

### 19. 同一终端里不同命令的 hex 格式不统一

- **日期**：2026-11-17
- **现象**：Pwn 靶机的 `seed 0x7ffd0208 0x401234` 正常，但 `trig 0x4141...` 报 `bad hex`；去掉 `0x` 前缀后成功。
- **原因**：同一程序里不同子命令的解析器可能各写各的——有的接受 `0x` 前缀，有的只认纯十六进制串。
- **解法**：先看命令帮助/示例；一种格式不行就换另一种（带/不带 `0x`、有无空格、大小写）。
- **下次判断**：报 `bad hex`/`invalid number` 时，先怀疑格式而不是数据本身，用最小样例试格式。
