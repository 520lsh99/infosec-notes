## 一、目标

页面干净，但 HTML 注释里藏着 PHP 判断逻辑，满足条件即可拿 flag。

## 二、复现

### 2.1 看源码

打开靶机首页，按 `Ctrl + U`。在 HTML 底部注释里找到：

```php
<!--
$cat=$_GET['cat'];
echo $cat;
if($cat=='dog'){
    echo 'Syc{cat_cat_cat_cat}';
}
-->
```

### 2.2 带参数访问

```
http://靶机/?cat=dog
```

页面回显 `dog`，随后输出 flag。

最终提交：

```
CTF2{b4e4ec9a-d2c6-4f35-b565-57e468adde3b}
```

## 二·五、复盘四问

### 推理链（为什么这么做）

**第 1 步：为什么先 `Ctrl + U`**

- 我在想：页面本身没功能，答案大概率在注释或隐藏参数里。
- 验证：HTML 底部注释里有完整的 PHP 判断。
- 所以：不用猜，条件直接给了。

**第 2 步：为什么读懂 `$cat == 'dog'` 再动手**

- 我在想：要知道参数名（cat）、比较方式（`==`）、期望值（dog）。
- 验证：访问 `?cat=dog` 即出 flag。
- 所以：先读逻辑再构造请求，比盲试快。

### 载荷是怎么来的

- **来源**：直接从注释里抄条件。
- **`?cat=dog`**：参数名 `cat`，值 `dog`。
- **为什么不是 `?dog=cat`**：参数名和值不能反。

### 逐段解释

| 片段 | 作用 |
|---|---|
| `$_GET['cat']` | 取 URL 参数 |
| `echo $cat` | 回显用户输入（还可能反射 XSS） |
| `if($cat=='dog')` | 弱比较，命中即输出 flag |

### 失败尝试与坑

| 现象 | 原因 | 解决 |
|---|---|---|
| `?dog=cat` 没反应 | 参数名写反 | 参数名是 `cat` |
| 没找到注释 | 只看了页面顶部 | 源码拉到底部 |

### 自测

**Q1**：为什么注释会泄露逻辑？
**A**：开发者把测试/判断代码留在 HTML 注释里，随页面下发到客户端。

**Q2**：`==` 有什么风险？
**A**：弱比较会做类型转换，`"0"`、`"1e1"` 等可能意外相等。

**Q3**：修复两点？
**A**：注释里不留业务逻辑，比较用 `===`。

## 三、原理

| 点 | 说明 |
|---|---|
| `$_GET['cat']` | 从 URL 取 `cat` 参数 |
| 注释泄露逻辑 | 开发者把判断条件留在 HTML 注释里 |
| 弱比较 `==` | 本例是简单字符串比较 |

## 四、扩展：PHP 弱类型比较

如果遇到 `==` 且两侧类型不同，可以尝试：

``` 
?cat=0            # "0" == 0
?cat=1e1          # "1e1" == 10（科学计数法）
?cat[]=1          # 传数组，类型不同
?cat=dog%00       # 截断（老版本）
```

本题只需正常字符串 `dog`。

## 五、修复

- 不要把业务逻辑（尤其是判断条件）写进前端注释
- 用严格比较 `===`
- 不要在注释里留测试代码

## 六、踩坑

- 参数名是 `cat`，不是 `dog`（容易看反）
- 源码在 HTML 末尾，别只看开头

## 七、收获

- 养成「先看源码」的习惯：注释、调试代码、隐藏参数经常直接给答案。
- 记住 PHP 弱比较的几种常见绕过形态。
