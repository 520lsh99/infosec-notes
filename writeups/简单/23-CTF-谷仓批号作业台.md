# CTF 练习：谷仓批号作业台（JS 逆向 · 计算 32 位十六进制批号）

> 平台：CTF² / Daily Hack（Reverse · 简单 · 100 分）
> 环境：浏览器 + 页面内联 JavaScript
> 日期：2026-11-26
> 性质：平台提供的授权靶场

---

## 一、目标

页面把三批原料卡推进到「入库」后，出现「批号校验台」。
需要提交一个 **32 位小写十六进制批号**，校验通过后返回出库凭证（flag）。

页面里的校验脚本被打散、改名、掺入干扰分支，真正的合成规则只在一处调用。

## 二、拿源码

浏览器 `Ctrl + U` 或直接抓 HTML，关键脚本在 `<script>` 末尾（已混淆命名）：

```js
var _0x51c = [37,146,88,203,15,174,92,61,230,19,107,148,55,176,121,84];
var _0x2f8 = [92,31,165,74,208,57,130,99,41,186,73,22,151,68,204,117];

function _0x1b7(s){ 反转字符串 }

function _0x7a(a,b){
  var out = '';
  for (var i=0;i<16;i++){
    var v = ((a[i]<<1) + a[i] + (b[i]<<2) + b[i] + ((i<<3)+(i<<1)+i)) & 255;
    out += ('0'+v.toString(16)).slice(-2);
  }
  return out;
}

function _0x9d4(x){
  if ((x ^ x) === 0) return _0x7a(_0x51c, _0x2f8);   // 恒真
  return _0x1b7(x);                                   // 死代码
}

function _0x3b0(x){ return _0x1b7(x) === 'eert'; }    // 干扰
```

校验逻辑：

```js
if (_0x9d4(code) !== code) { 拒绝 }
fetch('/api/verify', {method:'POST', body: JSON.stringify({code})})
```

## 三、简化

| 混淆写法 | 化简 |
|---|---|
| `(a[i]<<1) + a[i]` | `3*a[i]` |
| `(b[i]<<2) + b[i]` | `5*b[i]` |
| `(i<<3) + (i<<1) + i` | `11*i` |
| `& 255` | `mod 256` |
| `(x ^ x) === 0` | **恒真**（任何数异或自己为 0） |

得到核心公式：

```
byte[i] = (3*a[i] + 5*b[i] + 11*i) mod 256
```

`_0x1b7`（反转）与 `'eert'` 分支都是死代码/干扰项。

## 四·五、推理链（为什么这么做）

### 第 1 步：为什么先把三张卡推进入库

- **我在想**：页面说明「三批全部入库后校验台才会出现」。
- **验证**：每张点两次（待检→复检→入库），`data-state` 变 2 → 校验区 `hidden` 被移除。
- **所以**：这是页面逻辑门槛，与逆向核心无关。

### 第 2 步：为什么抓 HTML 而不是只看页面

- **我在想**：需要「检验脚本」，而页面只显示结果。
- **验证**：用 `Invoke-WebRequest` 抓原始 HTML，`<script>` 里就是完整逻辑。
- **所以**：逆向对象到手。

### 第 3 步：为什么先找「真正的调用点」

- **我在想**：题面说脚本被打散、改名、掺了干扰分支（`_0x3b0` 判断 `eert`、`_0x1b7` 反转）。
- **验证**：沿着提交逻辑找到 `_0x9d4(code) !== code` 这一句。
- **所以**：只需要看懂 `_0x9d4`，其他都是烟幕。

### 第 4 步：为什么判定 `(x ^ x) === 0` 是死分支

- **我在想**：任何数异或自己，每一位都相同，结果必为 0。
- **所以**：`if` 恒真，`return _0x1b7(x)` 永远执行不到 —— `rev` 完全无关。

### 第 5 步：为什么把位运算化简

- **我在想**：`x<<1` 是 `2x`，所以 `(a<<1)+a = 3a`；`(b<<2)+b = 5b`；`(i<<3)+(i<<1)+i = 11i`。
- **所以**：整段混淆就是 `(3a + 5b + 11i) mod 256`。

### 第 6 步：为什么必须填这个常量

- **我在想**：`_0x9d4` 忽略输入、永远返回 `calc(a,b)`。
- **验证**：`check(code) === code` 的唯一解就是常量本身。
- **所以**：算出来直接填，不需要爆破。

## 五、为什么必须填这一串

`_0x9d4(code)` **忽略输入**，永远返回 `_0x7a(a,b)` 的结果。
所以：

```
check(任何输入) === 常量
```

要满足 `check(code) === code`，只能令 `code = 常量`。

## 六、提交

页面操作：

1. 三张批次卡各点两次（待检 → 复检 → 入库）
2. 出现「批号校验台」
3. 输入 `3b5c57f4695ee0f3d73e1ca31cf301ea`
4. 提交核验

接口层面等价于：

```
POST /api/verify
{"code":"3b5c57f4695ee0f3d73e1ca31cf301ea"}
```

返回：

```json
{"ok": true, "flag": "CTF2{68ab04ea-9012-4f9e-8fab-70765e0e65c1}"}
```

## 六·五、失败尝试与排除

| 尝试 | 结果 | 为什么失败 |
|---|---|---|
| 把三张卡只点一次 | 校验台不出现 | 每张需要两次（复检→入库） |
| 只看页面渲染、想从 DOM 找答案 | 什么都没有 | 真值只在 JS 里算，DOM 不存 |
| 以为 `rev()` 相关 | 算不出 | `(x^x)===0` 恒真，`rev` 是死代码 |
| 以为 `'eert'` 是线索 | 走偏 | 纯干扰（eert 反转 = tree） |
| 手工逐字节算 16 次 | 易错 | 先用脚本算，再手算 1~2 个抽查 |

## 七、技巧总结

| 技巧 | 说明 |
|---|---|
| 位运算还原乘法 | `x<<1 + x` = `3x`；`x<<2 + x` = `5x` |
| 死分支识别 | `(x^x)===0` 恒真；`return 反转` 永远不执行 |
| 常量陷阱 | 校验函数返回常量 → 直接抄结果 |
| `& 255` | 取低 8 位 |

## 八、自测

**Q1**：`(i<<3)+(i<<1)+i` 等于多少倍的 i？
**A**：11 倍（8+2+1）

**Q2**：为什么 `(x ^ x) === 0` 恒成立？
**A**：任何数与自身异或，每一位都相同 → 结果为 0

**Q3**：`571 mod 256` 是多少？
**A**：59（0x3b）

## 九、收获

- 学会把混淆的位运算还原成普通算式。
- 认识了「死分支 + 常量校验」这类逆向题的常见套路。
- 理解了「读代码就能算出答案」，不需要爆破。
