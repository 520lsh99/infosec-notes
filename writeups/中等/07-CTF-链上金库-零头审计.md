# CTF 练习：链上金库 · 零头审计（取整方向缺陷）

> 平台：CTF² / Daily Hack（Blockchain · Medium · 300 分）
> 环境：Kali Linux，通过 `openssl s_client` 连 TLS 对话终端
> 日期：2026-11-11
> 性质：平台提供的授权靶场

---

## 一、目标

金库声明了四条取整规则（R1~R4），实现里有两条方向与声明相反。要求：
1. 用真实存取积累证据；
2. 找出两条反向规则、排除合规规则；
3. 在 AUDIT 对质阶段回答方向、引用两条偏差>0 的日志、展示净收益 ≥10；
4. 全部通过后获得 flag。

## 二、环境

```
openssl s_client -connect xxxx.tcp-ctf2.dasctf.com:9999 -servername xxxx -quiet
```

连上后是一个**对话式终端**（`[探索] >` 提示符），支持命令：

| 命令 | 作用 |
|---|---|
| `STATUS` | 钱包、金库资产 T、份额总量 S、我的份额、报价 |
| `DEPOSIT n` | 存 n 金币，铸造份额 |
| `WITHDRAW w` | 取 w 金币，销毁份额 |
| `REDEEM n` | 赎回 n 份额，换金币 |
| `LOG` | 每笔交易的声明值 / 实际入账 / 偏差 |
| `JOURNAL` | R1~R4 声明 |
| `AUDIT` | 进入对质阶段（共四问） |
| `QUIT` | 断开 |

## 三、初始状态与规则

```
STATUS: 钱包=100 | T=1050 | S=1000 | 我的份额=0 | 报价=1
JOURNAL:
  R1: 铸造份额 = floor(存入 * S / T)，向下取整，不得多铸
  R2: 取款销毁份额 = ceil(取款 * S / T)，向上取整，不得少销
  R3: 赎回支付金币 = floor(份额 * T / S)，向下取整，不得多付
  R4: 报价 = floor(T / S)，恒为真
```

**创世比例 1050:1000 ≠ 1:1**，所以每次取整都有「零头」空间。

## 四、审计过程（逐笔对账）

| # | 操作 | 声明值 | 实际值 | 偏差 | 结论 |
|---|---|---|---|---|---|
| 001 | DEPOSIT 1 | 0 份额 | **1 份额** | 1 | R1 实际 ceil（声明 floor）❌ |
| 002 | REDEEM 1 | 1 金币 | 1 金币 | 0 | R3 实际 floor，与声明一致 ✅ |
| 003 | DEPOSIT 10 | 9 份额 | **10 份额** | 1 | R1 再次确认 ❌ |
| 004~011 | WITHDRAW 1（多次） | 1 份额 | **0 份额** | 1 | R2 实际 floor（声明 ceil）❌ |

**结论：R1、R2 方向反了，R3 是唯一合规的，R4 恒为真。**

## 五、利用缺陷获利

### 5.1 免费取款

R2 实际烧 0 份额，而 `T（1050）> S（1000）`，所以每取 1 金币：
- 金币 +1
- 金库资产 T −1
- 我的份额不变

重复直到 T ≈ S，最多能白拿 **T − S** 枚金币。

### 5.2 把份额变现

份额本身不算现金，要赎回：

```
REDEEM 10 → 支付 10 金币（R3 合规，floor(10 * T / S) = 10）
```

### 5.3 最终账目

```
初始：100 金币
赎回 +10，免费取款 +3
最终：111 金币 → 净利 11 ≥ 10 ✅
```

## 六、AUDIT 对质（四问）

| 问题 | 回答 |
|---|---|
| R1 声称向下取整，实现的实际方向？ | **up**（ceil） |
| R2 声称向上取整，实现的实际方向？ | **down**（floor） |
| 给出两条偏差>0 的日志编号（一条 DEPOSIT、一条 WITHDRAW，逗号分隔） | **001,004** |
| 唯一与声明完全一致的规则编号？ | **R3** |

> 注意：日志编号**不要带 `#`**，按「编号1,编号2」格式填纯数字。

## 六·五、复盘四问

### 推理链（为什么这么做）

**第 1 步：为什么先读 `JOURNAL` 再交易**

- 我在想：审计要有「声明基准」，否则看到偏差也不知道是谁的错。
- 验证：`JOURNAL` 拿到 R1~R4 的声明方向。
- 所以：后面每笔交易都能和声明逐条对照。

**第 2 步：为什么第一笔用 `DEPOSIT 1` 而不是大额**

- 我在想：`1050:1000` 比例下，存 1 金币理论份额 = `1×1000/1050 = 0.952`。
  声明 floor → 应该给 **0**；如果给了 1，说明实现是 ceil。
- 验证：`DEPOSIT 1` → 实得 1 份额，偏差 1。
- 所以：R1 方向反了（up）。

**第 3 步：为什么再存一次 `DEPOSIT 10`**

- 我在想：单次可能是边界特例，要复现。
- 验证：`10×1000/1050 = 9.52`，floor=9，实得 10 → 再次 ceil。
- 所以：R1 稳定反向，不是偶发。

**第 4 步：为什么用 `WITHDRAW 1` 反复试**

- 我在想：R2 声称 ceil，如果实现 floor，取 1 金币应销毁 0 份额（`1×1000/1050=0.95`，floor=0）。
- 验证：多次 `WITHDRAW 1`，每次销毁 0 份额、金币 +1。
- 所以：R2 也是 floor，方向反了。

**第 5 步：为什么还要测 `REDEEM`**

- 我在想：不能假设全部规则都错，要留一个对照组。
- 验证：`REDEEM 1` 支付 1 金币，与声明 floor 一致。
- 所以：R3 合规，R4 恒真 → 只有 R1、R2 反向。

**第 6 步：为什么最后必须 `REDEEM`**

- 我在想：AUDIT 的「净收益」按金币算，份额只是凭证。
- 验证：不赎回时现金没增加，达不到 ≥10。
- 所以：先白拿金币（R2），再把份额赎回变现（R3）。

### 命令/数字是怎么来的

- **来源**：手工逐条输入，无脚本。
- **为什么是 1 和 10**：小额能把取整零头放大成可见偏差；大额用来复现。
- **为什么是 10 份额赎回**：份额总额 10，一次赎回正好变现。

### 逐段解释

| 命令 | 作用 |
|---|---|
| `STATUS` | 拿到 T、S、我的份额、报价，作为后续计算基准 |
| `DEPOSIT 1` / `DEPOSIT 10` | 验证 R1 方向（声明 floor，实际 ceil） |
| `WITHDRAW 1` ×N | 验证 R2 方向（声明 ceil，实际 floor），同时白拿金币 |
| `REDEEM 1` | 对照组，确认 R3 合规 |
| `LOG` | 取「声明值 vs 实际值 vs 偏差」，作为 AUDIT 的证据 |
| `AUDIT` | 回答四问：方向、两条偏差日志、合规规则 |

### 失败尝试与坑

| 尝试 | 结果 | 原因 |
|---|---|---|
| 一次粘贴 10 行命令 | 命令被吞/拼接 | 对话终端缓冲区小，必须一条一条发 |
| 日志编号写 `#001` | 被拒 | 格式要求纯数字 `001,004` |
| 只看份额增加就以为赚了 | 不达标 | 净收益按金币算，份额要 REDEEM |
| 中途断开重连 | 金库状态可能重置 | 一次连接内做完 |

### 自测

**Q1**：为什么存 1 金币能看出 R1 方向？
**A**：`1×1000/1050=0.952`，floor=0、ceil=1，实测得 1 说明是 ceil。

**Q2**：R2 反向为什么能白拿金币？
**A**：取 1 金币本应销毁 0.95 份额（ceil=1），实际销毁 0，金币却到账。

**Q3**：为什么净利要按金币计？
**A**：份额不是现金，必须 REDEEM 换成金币才算真实收益。

## 七、原理与危害

取整方向决定了「零头归谁」：

| 规则 | 正确方向 | 反向后果 |
|---|---|---|
| 铸造份额 | 向下（少铸） | 多铸 → 用户白得份额 |
| 销毁份额 | 向上（多销） | 少销 → 用户白拿金币 |
| 赎回支付 | 向下（少付） | 多付 → 金库多掏钱 |

创世比例不是 1:1 时，每次交易的零头都会被放大，**攻击者可以通过大量小额交易把零头全部吸走**（经济学上叫「粉尘攻击 / 取整套利」）。

**真实世界案例**：DeFi 金库、质押协议、AMM 里对 `floor/ceil` 用错方向，会直接造成资金损失。

## 八、修复建议

1. **统一取整方向**：铸造向下、销毁向上、赎回向下，全部按「保护金库」原则实现。
2. **用定点数/安全数学库**：`SafeMath`、`PRBMath`、`FixedPoint` 等，避免精度丢失。
3. **边界测试**：对 `T/S` 非整除的比例写单元测试，断言偏差方向。
4. **审计日志**：像本题一样记录「声明值 vs 实际值」，异常偏差应告警。
5. **限制粉尘交易**：最小交易额、手续费，降低取整套利空间。

## 九、踩坑

1. **对话终端不能批量粘贴**：一次粘 10 行会缓冲区错乱，命令被吞或拼接，出现「数量必须是整数」「格式: 命令 数量」。**一条一条发**。
2. **日志编号格式**：带 `#` 会被拒绝，按提示填 `001,004`。
3. **净利按现金算**：份额不计入净收益，必须 `REDEEM` 换成金币才达标。
4. **重连可能重置金库**：尽量在一次连接里做完，别中途断开。

## 十、收获

- 理解了「取整方向」在金融合约里的安全含义。
- 学会用**逐笔对账**找实现与声明的差异（审计的基本功）。
- 认识到「比例不是 1:1 时，零头就是攻击面」。
- 对话式终端的交互纪律：一条一条来。
